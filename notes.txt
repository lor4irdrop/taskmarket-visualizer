Taskmarket live market visualizer — notes.txt
Bounty: TSK-BRK611AN "Build and host Taskmarket's live market visualizer (50 OUSD)"

Live URL: https://lor4irdrop.github.io/taskmarket-visualizer/
Repo URL: https://github.com/lor4irdrop/taskmarket-visualizer

Stack: static HTML + CSS + vanilla JavaScript (no framework, no external JS
libraries, no analytics, no wallet). Fonts: Instrument Serif + Inter Tight
(Google Fonts, per the Taskmarket brand kit). Hosted on GitHub Pages.

Endpoints used (https://api.taskmarket.dev, no key, per chain Tempo 4217 / Base 8453):
  /api/market/stats
  /api/stats/breakdowns
  /api/stats/platform-time-series (ranges 7d/30d/90d/all)
  /api/stats/activity-heatmap (dimensions hourOfWeek, mode)
  /api/stats/activity-feed
  /api/tasks (paginated, for distinct posters per week + concentration + open tasks)

Refresh method / frequency: scheduled server-side fetch, at least hourly, from
the operator's server: node scripts/fetch-data.mjs fetches the API and bakes
the results into data/*.json (and regenerates og.png from the live numbers),
then the files are published to GitHub Pages via the GitHub Contents API
(scripts/gh.py). The page reads only the static data/*.json files (the API
forbids browser requests from other origins). A visible "data as of" time (WIB)
is shown in the header and footer. Data is cached in the static build for up
to 1 hour (>= 60s required). The .github/workflows/ files for GitHub
Actions-based refresh are included in the repo under docs/workflows/ — copy
them to .github/workflows/ to switch the refresh to Actions (needs a token
with the workflow scope, or the GitHub web UI).

Deploy command: ./deploy.sh
(Equivalent: node scripts/fetch-data.mjs && python3 scripts/make_og.py && python3 scripts/gh.py upload lor4irdrop taskmarket-visualizer . — refreshes the data and publishes everything to GitHub Pages. To run locally: node scripts/fetch-data.mjs && python3 -m http.server 8000.)
